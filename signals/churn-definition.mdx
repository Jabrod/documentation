---
title: "Churn definition"
description: "What counts as a customer leaving, and the window Signals predicts over."
---

The model learns from customers who left in the past, so "left" must be defined first. Pick one definition:

| Definition | A customer has churned when | Needs |
| --- | --- | --- |
| **Cancelled** | They have a cancellation date | `cancelled_at` in the customers file |
| **Stopped paying** | No successful payment for N days after their last one (default 45) | A payments file |
| **Went quiet** | No usage events for N days (default 30) | A usage events file. For products without billing data. |

Signals suggests a default from the files you uploaded, and shows how many customers churned under each rule before you choose.

## Prediction window

A score answers: **how likely is this customer to churn in the next 30 days?** The window can be set from 14 to 90 days. A longer window gives earlier warning with less precision.
